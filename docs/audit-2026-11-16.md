## 二、P0：必须先修的根因（一个根因带一片症状）

### RC1 · 状态写入竞态（最严重，会静默损坏数据）

**现象**
- `Delete` 键删除选中节点：**边被删了，节点还在**，而且立刻写进 localStorage
- `⌘D` 复制：**完全没反应**，还把当前选择清空了
- 选中图片节点生成：900ms 后提示词从「把这张图改成赛博朋克风格」**变回**「雨夜的霓虹街角…」，比例从 16:9 变回 3:4
- 生成后 900ms 内再加节点：新节点被丢弃（7→6）

**根因**（已读代码核实）
1. `shell.jsx` 的 `updateCanvas` 用渲染闭包里的 `state.canvases` 重建数组，而不是函数式 `setState`
2. `removeSelected` / `duplicate` 在同一个 tick 里先后写 `nodes` 和 `edges`，第二次用的是**旧的**画布快照 → 把第一次的改动覆盖掉

**修法**：`updateCanvas` 改函数式更新；`onChange` 支持一次提交多个字段（nodes+edges 合并成一次写入）；编辑器内的写入口统一走一个批处理函数。

### RC2 · 模型名全都不显示

**现象**：输入条、生图工作台、偏好设置三处的模型列表，名字是空的。工作台菜单实际渲染成 `· 默认渠道`；偏好设置下拉两个模型选项**文字完全一样**，无法区分。

**根因**（已核实）：`modelsWithCap()` 返回 `{ key, model, channel }`，但三处 UI 都写 `m.label`（undefined）。
`pages/canvas.jsx:436`、`pages/studio.jsx:138`、`pages/config.jsx:211`

**修法**：在 `store.js` 的 `modelsWithCap` 里补 `label` 字段，三处不用改；或统一改成 `m.model.label`。

### RC3 · toast 遮住输入条，2.2 秒内整条按钮点不动

**现象**：每次 toast（如「开始生成」）出现后约 2.2s，输入条上 7 个按钮（参考/比例/张数/模型/包组/删除/发送）全部点不动；`elementFromPoint` 命中的是 toast。

**根因**（已核实）：`styles.css:26` 的 `.cf-app > :not(.cf-ambient) { position: relative }`（特异度 0,2,0）覆盖了 `.cf-toast { position: fixed }`（0,1,0），toast 变成 grid 子项 → 撑成 1440×33 全宽条 + `pointer-events: auto`。

**修法**：把 toast 排除出这条通用规则（`pointer-events: none` + 保持 fixed），或给 toast 单开一层。

### RC4 · 分组选不中、拖不动、删不掉

**现象**：`.cf-node.is-group` 与 `.cf-node-group-head` 的 `pointer-events` 都是 `none`；点击分组标题 `elementFromPoint` 返回 `.cf-stage`；拖动无效；选中后 Delete 无变化。连带：**组内节点无法作为连线目标**。

**根因**（已核实）：我把分组标题的类名从 `.cf-node-head` 改成了 `.cf-node-group-head`，但 `pointer-events: auto` 那条规则还写着旧的 `.cf-node.is-group .cf-node-head`，失配。

**修法**：分组框 `pointer-events: none`、标签 `auto`；分组可通过点标签或边框选中；连线命中判定忽略分组遮挡。

### RC5 · 空格平移从节点上失效；H 工具没接线

**现象**：空白处空格拖动正常（Δ−150/−80）；从节点上空格拖动位移 0。点 H（移动工具）后光标没变、拖空白也没反应。

**根因**：节点 `pointerdown` 先 `stopPropagation()`，且没判断「当前是空格/移动工具」；`tool === 'pan'` 从未被消费。

**修法**：`nodeDown` 里若 `space` 或 `tool === 'pan'` 直接返回交给舞台；`pan` 工具接入光标与拖动逻辑。

### RC6 · 缩放节点比例取反，还强制锁死所有节点

**现象**：3:4 的图片节点向右拖把手 → 变成 360×270（4:3）；文本/配置节点也被锁，文本 230×160 拖成 350×350 正方形。

**根因**（已核实）：`resize.current.ratio = rh / rw`（3:4 → 1.333），然后 `h = w / 1.333`，方向反了；`locked: node.locked !== false` 让没有 `locked` 字段的节点默认成 true。

**修法**：`h = w * (rh/rw)`；只有图片节点且 `locked === true` 才锁比例，其余默认自由缩放。

### RC7 · 新建画布被演示场景预填

**现象**：点「新建画布」得到的不是空白画布，而是 6 节点 4 连线的「霓虹街角」；列表行显示「未命名画布 · 6 个节点 · 4 条连线」。

**根因**（已核实）：`shell.jsx` 的 `createCanvas` = `{ ...newCanvas(), ...seedCanvas() }`，把演示内容写进了每一张新画布。

**修法**：只有「首次启动且完全没有画布」时才种一张示例；新建一律空白。

### RC8 · 坏数据直接白屏，用户无法自救

**现象**：把 localStorage 写成 `{"canvases":{}}` 或 `{"canvases":"abc"}` 后刷新 → **整页白屏**，顶栏都没有，再刷新仍白屏，坏数据留在原地。`TypeError: state.canvases.find is not a function`

**根因**：`currentView`/`openCanvas` 直接假设 `state.canvases` 是数组；错误边界只包了页面区，**App 根级没包**。

**修法**：读盘时做 schema 清洗（非数组回落空数组、节点补默认字段、剔除 null）；根级也套一层 Boundary。

## 六、需要你决策的三件事

1. **先修哪批？** 建议 P0（3.5 人日）——它修的是「数据会被静默改坏」和「按钮点不动」，不修的话后面加功能都建立在不稳的地基上。
